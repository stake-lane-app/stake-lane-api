## Architecture

![System Architecture](imgs/architecture.png)

The API follows a layered architecture pattern:
- **Phoenix Web Layer**: RESTful API endpoints and request handling
- **Business Logic Layer**: Core application logic organized by domain contexts
- **Data Layer**: Ecto schemas and database operations with PostgreSQL + PostGIS
- **External Services**: Integration with API-Football for real-time match data
- **Background Jobs**: Oban workers for asynchronous data synchronization
- **Authentication**: Pow framework handling user sessions and OAuth providers

## Installation & Setup

1. Clone the repository:
```bash
git clone <repository-url>
cd stake_lane_api
```

2. Install dependencies:
```bash
mix deps.get
```

3. Start PostgreSQL with PostGIS:
```bash
docker-compose up -d
```

4. Setup the database:
```bash
mix setup
# This runs: mix deps.get, ecto.create, ecto.migrate, and seeds
```

5. Start the Phoenix server:
```bash
mix phx.server
```

The API will be available at `http://localhost:4000`

## Background Jobs

The application uses **Oban** for reliable background job processing.

**Workers**:
- `UpdateLeagues` - Syncs league data from API Football
- `UpdateFixtures` - Updates fixture information
- `UpsertCountries` - Syncs country data
- `UpsertFixtures` - Creates/updates fixtures
- `UpsertTeams` - Syncs team data

Jobs are scheduled and processed asynchronously to keep the database synchronized with the latest football data.

## API Endpoints

### Public Endpoints (Authentication Required - See Session Management)

**Base URL**: `/api/v1`

#### Authentication
```
POST   /api/v1/registration              # Create new user account
POST   /api/v1/session                   # Login (email/password)
DELETE /api/v1/session                   # Logout
POST   /api/v1/session/renew             # Renew session token
GET    /api/v1/auth/:provider/new        # OAuth provider authentication
POST   /api/v1/auth/:provider/callback   # OAuth callback
```

#### Protected Endpoints (Require Authentication)

**Leagues**
```
GET    /api/v1/leagues                   # List available leagues
GET    /api/v1/leagues/my                # Get user's followed leagues
POST   /api/v1/leagues/my                # Follow a league
```

**Teams**
```
GET    /api/v1/teams                     # List teams
POST   /api/v1/teams                     # Follow a team
DELETE /api/v1/teams                     # Unfollow a team
GET    /api/v1/teams/leagues             # Get leagues for teams
```

**Fixtures**
```
GET    /api/v1/fixtures/my               # Get fixtures for user's leagues/teams
```

**Predictions**
```
POST   /api/v1/predictions               # Create a prediction for a fixture
```

**Countries**
```
GET    /api/v1/countries                 # List available countries
```

## Deployment

### Deploy to Google App Engine

1. Ensure you're authenticated with Google Cloud:
```bash
gcloud auth login
gcloud config set project bolao-hub
```

2. Configure environment variables in `app.yaml`

3. Deploy the application:
```bash
gcloud app deploy
```

### Running Migrations on Remote Environment

1. SSH into the App Engine instance:
```bash
gcloud app instances ssh "aef-default-0--1--5-jkhw" \
  --service "default" \
  --version "0-1-5" \
  --project "bolao-hub"
```

2. Enter the container:
```bash
docker exec -it gaeapp bash
```

3. Run migrations:
```bash
bin/stake_lane_api migrate
```

Refer to the [Distillery Migration Guide](https://hexdocs.pm/distillery/guides/running_migrations.html) for more details.
